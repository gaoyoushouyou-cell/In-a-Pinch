# 挟みゲーム IN A PINCH(ブラウザ版)

`In_a_Pinch_app_5.py`(Python/tkinter版)のルール・画面構成・AIをそのまま踏襲した、
**ブラウザだけで動く**版です。ビルド不要・追加インストール不要の素のHTML/CSS/JavaScriptで
できているので、GitHub Pagesにそのまま置けばスマホでもパソコンでも遊べます。

## 収録内容(Python版との対応)

- ゲームエンジン(配置・移動・壁挟み・接触制限・挟み義務の連鎖・千日手判定)を完全移植
- 探索AI 8段階(ランダム〜神。『達人』は『最強』と同じ読みで思考時間2秒)+ テンプレート専用の最強AI「奥義」
- AI戦は先手・後手・ランダムから手番を選べる。対人戦(同じ画面)は将棋の対局時計にならった
  持ち時間を選べる(1分将棋・10秒将棋・切れ負け・持ち時間+秒読み・フィッシャー・カスタム)
- 対局中の形勢表示(優勢・劣勢の%)。学習型AIの評価値を勝率に直したもの(Texel 法で学習した
  評価値なので sigmoid(評価値/100) がそのまま「強いAI同士で続けた場合の勝率」の目安になる)
  - メニューでオン・オフ。持ち時間なしの対局は既定でオン、持ち時間ありの対人戦とオンライン対戦は
    既定でオフ(どちらもオンにできる。オンライン対戦は対局を作った人が決め、リンクで相手にも伝わる)
  - 読みは専用の Web Worker で1局面0.6秒(Python版は別スレッドで1秒)。相手AIの思考中は読まず、
    AI同士の対戦では形勢を読み終えてから次のAIが考える
  - 表示した対局は棋譜CSVに `# 形勢表示: あり` と記録し、対戦履歴・感想戦にも表示する
    (`dev/human_kifu_lab.py` の集計では人間の手を `human+形勢` / `pvp+形勢` として区別)
- 感想戦の勝率グラフと悪手判定
  - 感想戦を開くと、各局面を形勢表示と同じ評価役で順に読み(1局面0.6秒、Python版は1秒)、
    先手の勝率の推移をグラフにする(クリックでその手へ移動)
  - 1手ごとに「指した側の勝率の落ち幅」で判定: 8%以上 疑問手(?!)・15%以上 悪手(?)・30%以上 大悪手(??)。
    AIの最善手と同じ手・他に指せる手がない手は損失0。判定した手にはAIの最善手も示す
  - 先手・後手それぞれの大悪手・悪手・疑問手の数と平均損失を表示し、前後の疑問手・悪手へ移動できる
  - 解析結果は対戦履歴の記録に保存し、次からはすぐ表示する(Python版は棋譜CSVの隣の `….analysis.json`)
  - 勝率グラフでは、どちらかの勝ちを読み切った(詰みが見えた)局面の範囲を金色の帯で強調する
    (先手の詰みは上端、後手の詰みは下端に濃い線)。「◆ 詰みを読み切った局面へ」で移動できる
- 感想戦の「AIの検討」(Python版にも同じ機能。樹形図は別ウィンドウで開き、選んだ手順の局面は感想戦の盤に出る)
  - どの局面でも、解析で読んだその局面の最善手を表示し、盤に青い矢印で示す(チェックで消せる)
  - 「じっくり読む」で1局面を5秒読み直し、最善手と読み筋(先の手順)を表示する。
    学習型の読みで決着が見えなければ、詰み探索(11手まで)でも手番側の詰みを確かめる
  - 詰みを読み切った局面では「詰み手順を見る(樹形図)」で手順を樹形図にする。勝つ側は最短で詰ませる1手、
    負ける側は指せる手をすべて枝にして、長く粘る受けほど上に並べる(1行目が本線)。どの枝の先も詰みの局面で終わる。
    同じ返し手でその場で詰む受けは1つにまとめて「他N」と表示。手をクリックするとその局面を盤に出し、
    1手ずつ進める・戻す・本線を詰みまで進めることができる
  - 詰みの証明は対局AIの詰み探索(`MateSearch`)と同じ(千日手は負ける側の逃れとみなす)。挟む手だけで
    詰まなければ攻め方の全部の手も読む。枝が多いときは一部を「続きを読む…」として後回しにし、押すとその先を読む
  - 読みは専用の Web Worker で行い、感想戦の解析(勝率グラフ)と並行して動く
  - 基準は実戦の棋譜20局で確認: 強いAI(奥義・自己対戦)は平均損失0.7〜1.5%でほぼ印が付かず、
    人間や上級AIは平均5〜16%
- レート(AI戦の結果と指し手の質から計算。ナビの「レート」で推移のグラフと対局ごとの記録を見られる)
  - AI戦を1局終えると、裏で指し手を解析して(感想戦の悪手判定と同じ物差し)その対局のパフォーマンスを出す:
    結果 = 相手AIのレート ±400、内容 = 平均損失をレートに換算した値、その平均
  - 最初の5局は暫定(パフォーマンスの平均)、以降は レート + 0.2×(パフォーマンス − レート) で更新
  - 対象は AI戦のみ。形勢表示あり・待ったを使った・感想戦から再開した対局は数えない(理由を表示)
  - 記録はこの端末のブラウザ(localStorage `hasami:rating:v1`)。ページを閉じても計算待ちの対局は次に開いたとき続きから計算
  - AIのレート(ランダム 0 / 初級 764 / 中級 1466 / 上級 1742 / 達人 1897 / 最強 1933 / 究極 2518 / 神 2597 / 奥義 2814)は
    `dev/rating_ladder.js` で隣のレベルどうしを本番の持ち時間で対戦させ(特化テンプレート、各8〜40局)、
    `dev/rating_calib.js` で求めたもの。全勝した組の差は「少なくともこのくらい」の値。計算式は `rating.js`
- メニューの設定はこの端末のブラウザに保存され、対戦画面から戻っても前回の設定のまま
  - 「究極」「神」「奥義」は学習型探索AI(高速探索エンジン + 自己対戦で学習した評価関数)。
    Python版と同じ重み・同じ探索で、持ち時間は従来どおり
  - 「奥義」はさらに、駒の上下左右4マスの形(局所パターン、55通り)の点数も自己対戦から学習
    (同じ持ち時間で以前の「奥義」に +87 Elo。経緯は戦術レポート「11. 追記」)
  - 「初級」〜「最強」(MinimaxAI)は、勝ちが決まってからの引き延ばしをなくすため、通常の探索の前に
    各レベルの読みの深さ以内の詰みだけを読む(詰み探索。挟む手中心で、1局面平均2ミリ秒)。初級・上級は
    さらに、読みの末端の「挟んだだけ」の水増し評価を消す静止探索も使う。AI同士の自己対戦の平均手数は
    初級 63→32手・上級 61→46手・最強 67→50手に縮んだ。強さは旧版とほぼ同じ(どのレベルも誤差の範囲なので、
    下のAIのレートは据え置き。経緯は戦術レポート「12. 追記」)
  - AIの思考は Web Worker(裏方のスレッド)で行うので、長考中も画面は固まりません
- チュートリアル(実際に盤を操作して覚える12レッスン)/ 戦略コラム(8本)/ 戦術レポート(データ付き長文)
  - 駒の置き方・動かし方から、挟む・挟まれたら逃げる・置けない場所・壁・角・接触制限まで、
    1レッスン1ルールで本物のルールエンジンの盤を触りながら進む(ヒント・やり直しつき)
  - 指せない手をクリックすると理由(「斜めには進めません」「C3とE3の間なので…」など)を表示
  - 最後のレッスンから、そのまま弱めのAIとの練習対局へ。進み具合はこの端末のブラウザに保存
- 詰めピンチ(詰将棋ふうの問題集、70問 + その場で自動作問)
  - あなたは毎手「相手の駒を挟む手」を指し、相手の義務の駒を動けなくすれば詰み。
    相手は専用ソルバーで「最も長く粘る受け」を返し、詰みを逃すとその場で逃れを示す
  - 全問、最短手数と唯一解を証明済み。問題は実戦の棋譜と学習型AIの自己対戦から
    `tsume_lab.js` で発掘している(下の「詰めピンチの作り方」参照)
- 対戦履歴・感想戦(棋譜の並べ直し)
  - Python版はCSVファイルとして保存していましたが、ブラウザ版は
    **この端末のブラウザ内(localStorage)** に保存します。「対戦履歴」画面から
    いつでもCSVとしてダウンロードもできます。チェックボックスで複数の対局を選ぶと
    (「すべて」「最新10件」などの一括選択あり)、まとめて1つのZIPでダウンロードできます。
  - LINEのアプリ内ブラウザはダウンロードできないため、ダウンロードを押すと
    選んだ記録をURL(`#kifu=`)に載せて `?openExternalBrowser=1` で外部ブラウザに
    開き直し、そちらの履歴に取り込んでから保存してもらいます(CSVのコピーも可)。
- オンライン対戦(「手番リンク」方式)
  - Python版はTCPで直接接続していましたが、GitHub Pagesは「サーバーの無い
    静的サイト」なので直接接続はできません。代わりに、指した手をURLに
    埋め込んで相手と送り合う **非同期の通信対局** を用意しています
    (LINEやメールでリンクを送り合うイメージです)。

## 動作確認だけしたい場合

`index.html` をダブルクリックして開くだけで、メニュー・チュートリアル・戦略コラム・
戦術レポートはそのまま見られます。AI対戦まで試したい場合は、ブラウザの制限で
Web Workerがうまく動かないことがあるため、下記のどれかで簡易サーバーを立てて
から開くことをおすすめします(公開後のGitHub Pagesでは何もしなくても動きます)。

```bash
# このフォルダの中で実行してください
python -m http.server 8080
```

実行したら `http://localhost:8080/` を開いてください。

## GitHub Pagesで公開する手順(初めての方向け)

以下はすべて無料でできます。何かの操作でつまずいたら、そのエラーメッセージで
検索すると大抵解決します。

### 1. GitHubアカウントを作る(すでにお持ちならスキップ)

https://github.com/ を開き、右上の「Sign up」からアカウントを作成してください。

### 2. 新しいリポジトリ(保管場所)を作る

1. GitHubにログインした状態で右上の「+」→「New repository」をクリック
2. Repository name に好きな名前を入力(例: `hasami-game-web`)
3. Public(公開)を選択
4. 「Add a README file」などのチェックは **入れない**(このフォルダに既にファイルがあるため)
5. 「Create repository」をクリック

作成すると `https://github.com/(あなたのユーザー名)/hasami-game-web` のようなページが
表示され、そこに `git remote add ...` から始まるコマンド例が載っています。

### 3. このフォルダをGitHubに送る

このフォルダは `git init` 済みで、ファイルは `git add` までしてありますが、
**コミット(記録の確定)はまだ行っていません**。このPCにはまだ「あなたが誰か」の
git設定が入っていなかったためです。お使いのターミナル(コマンドプロンプト/
PowerShell/ターミナル)で、この `hasami-web` フォルダに移動してから、
以下を1行ずつ実行してください(名前とメールアドレスは何でも構いません。
`(あなたのユーザー名)` と `hasami-game-web` は手順2で作った実際の値に
置き換えてください)。

```bash
git config --global user.name "あなたの名前"
git config --global user.email "you@example.com"
git commit -m "挟みゲームのブラウザ版を追加"
git branch -M main
git remote add origin https://github.com/(あなたのユーザー名)/hasami-game-web.git
git push -u origin main
```

(もしこのフォルダがまだ `git init` されていない場合は、`git config` の前に
`git init` と `git add .` を実行してください。)

`git push` の際にGitHubのユーザー名・パスワードを聞かれた場合、今のGitHubは
パスワードではなく「Personal Access Token」という専用の文字列が必要です。
聞かれたら https://github.com/settings/tokens から
「Generate new token (classic)」→ `repo` にチェック → 発行されたトークンを
パスワード欄に貼り付けてください。一度ログイン情報を保存すれば次回からは不要です。

すでに `git init` 済み(このフォルダがgitリポジトリになっている)場合は、
`git init` は省略して構いません。

### 4. GitHub Pagesを有効にする

1. GitHub上のリポジトリページで「Settings」タブを開く
2. 左メニューの「Pages」を開く
3. 「Build and deployment」の「Source」を **Deploy from a branch** にする
4. 「Branch」を **main** / フォルダを **/(root)** にして「Save」
5. 1〜2分待つと、ページ上部に
   `https://(あなたのユーザー名).github.io/hasami-game-web/` という
   URLが表示されます。これが完成した公開URLです。

このURLを開けば、スマホでもパソコンでも同じように遊べます。
URLをそのまま人に送れば、その人もブラウザだけで遊べます。

### 5. 更新したくなったら

ファイルを直したあと、同じフォルダで次を実行するだけで反映されます
(数十秒〜数分で公開ページにも反映されます)。

```bash
git add .
git commit -m "更新内容のメモ"
git push
```

## 「オンライン対戦(手番リンク)」の使い方

1. メニュー右上「🌐 オンライン対戦」を開く
2. 盤面サイズなどを決めて「対局を作ってリンクを発行」
3. 表示されたリンクをコピーして、対戦したい相手に送る(LINE・メール等)
4. 相手がリンクを開くと同じ盤面が再現され、相手の手番から続けられます
5. 手を指すたびに新しいリンクが作られるので、それを送り返し合うことで
   対局が進みます(将棋の郵便対局のようなイメージです)。

サーバーを介さずURLだけで手を交換する方式のため、常時接続や部屋番号は不要ですが、
同時に着手はできません(交互にリンクを送り合う形式です)。

## 詰めピンチの作り方(開発者向け)

1. **発掘** — 実戦の棋譜と学習型AIの速い自己対戦の全局面をソルバーで調べ、詰む局面を集める
   ```bash
   node tsume_lab.js mine-kifu ../kifu_logs out/kifu.jsonl
   node tsume_lab.js mine-self t7 1 400 out/t7_1.jsonl
   ```
2. **選別** — 唯一解・初手の候補2つ以上を満たすものを選び、自己対戦由来は不要駒を除去、
   対称形の重複を除いて、カテゴリごとに `tsume-data.js` へ書き出す
   ```bash
   node tsume_lab.js build out/*.jsonl
   ```
3. **検証** — `node test_node.js` が全問の手数・唯一解・主手順を独立に再検証し、
   ソルバー自体も clone() ベースの素朴な参照実装と突き合わせる
